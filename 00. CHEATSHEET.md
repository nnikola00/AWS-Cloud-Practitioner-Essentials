## 1. Master service table

### 1.1 Compute

| Service | What it does | Key facts / when to use | M |
|---|---|---|---|
| **Amazon EC2** | Virtual machines in the cloud — you choose OS, CPU, memory, storage, network | **Unmanaged**: AWS runs the hardware and hypervisor, **you patch the OS**. Pay per second/hour from launch to stop. Lives in **one AZ** | 1 |
| **AMI (Amazon Machine Image)** | The template an instance launches from: OS, storage setup, architecture, permissions, pre-installed software | **Region-scoped** — copy it to use elsewhere. Sources: AWS-provided, your own "golden image", Marketplace, community | 1 |
| **EC2 Auto Scaling** | Automatically adjusts the number of instances to match demand | **Min / desired / max.** Desired is what launches (defaults to min if unset). **Dynamic** (reactive), **predictive** (ML), **scheduled**. Driven by CloudWatch | 1 |
| **Elastic Load Balancing (ELB)** | Single point of contact that distributes traffic across targets and health-checks them | **ALB** = L7 HTTP, routes on path/host/header. **NLB** = L4 TCP/UDP, ultra-low latency. **GWLB** = third-party appliances. Hides churning instance IPs | 1 |
| **AWS Lambda** | Runs your code in response to an event; no servers to manage | **15-minute max**, 128 MB–10 GB memory, **stateless**, billed **per millisecond**. Triggers: S3, API Gateway, SNS/SQS, EventBridge, DynamoDB | 2 |
| **Amazon ECS** | AWS's own container **orchestration** service | Simpler, AWS-native, no control-plane fee — but AWS-specific. Runs on **EC2** (you manage servers) or **Fargate** (serverless) | 2 |
| **Amazon EKS** | Managed **Kubernetes** | Open-source and **portable** off AWS; more complex; hourly control-plane fee. Also EC2 or Fargate | 2 |
| **AWS Fargate** | Serverless **compute engine** that containers run on | **Not an alternative to ECS/EKS** — it replaces **EC2 underneath** them. No servers to patch; pay per container vCPU + memory | 2 |
| **Amazon ECR** | Stores, versions, and scans container images (OCI standard) | `docker push` / `pull`. Image : container :: AMI : EC2 instance | 2 |
| **AWS Elastic Beanstalk** | Upload web app code; AWS provisions EC2, ELB, and Auto Scaling for you | **PaaS**, but the resources are **yours and visible**. Java, .NET, Python, Node.js, PHP, Ruby, Go, Docker. **Not serverless** | 2 |
| **AWS Batch** | Runs large-scale **batch** jobs, scheduling and scaling compute automatically | For **long, parallel, interruption-tolerant** work. Pairs with **Spot**. The answer when Lambda's 15-minute cap rules it out | 2 |
| **Amazon Lightsail** | Simple VPS, storage, database and networking at a **fixed monthly price** | Small business, blogs (one-click WordPress), dev/test, learning. Signal: *"predictable pricing", "simple", "minimal AWS expertise"* | 2 |
| **AWS Outposts** | AWS-managed racks installed **in your own data center** | **Hybrid.** For very low latency to local systems, or **data residency** that forbids data leaving the building | 2 |
| **AWS Compute Optimizer** | Analyzes real utilization and recommends instance types and sizes | Covers EC2, EBS, Lambda, Fargate. Catches **over- *and* under-provisioning** | 12 |

### 1.2 Application integration

| Service | What it does | Key facts / when to use | M |
|---|---|---|---|
| **Amazon SQS** | Message **queue** — a producer drops messages in, a consumer pulls, processes, deletes | **One message → one consumer.** Messages **persist** if the consumer is down, so it **buffers work**. Decouples fast producers from slow consumers | 1 |
| **Amazon SNS** | **Pub/sub** — publish to a topic, SNS **pushes** to all subscribers | **One message → many recipients** (fan-out). Subscribers: Lambda, SQS, HTTP, email, SMS, mobile push | 1 |

| **Amazon API Gateway** | Create, publish, maintain, monitor, and secure **APIs** at any scale | The "front desk" for an application — auth, throttling, routing | 4 |

### 1.3 Networking & content delivery

| Service | What it does | Key facts / when to use | M |
|---|---|---|---|
| **Amazon VPC** | Your logically isolated network in AWS, with IP ranges you define | Lives in **one Region**, **spans its AZs**. Benefits: security, control, convenience | 4 |
| **Subnet** | A range of IPs inside a VPC | **One subnet = one AZ.** **Public** (route to an IGW, dashed in diagrams) or **private** (solid) | 4 |
| **Internet gateway (IGW)** | The VPC's public front door — connects it to the internet | Attach to the VPC. **Both directions.** A subnet is "public" only because it has a **route** to one | 4 |
| **NAT gateway** | Lets private-subnet instances reach out; nothing can initiate inward | **Outbound only.** Classic use: private database servers downloading patches | 4 |
| **Virtual private gateway (VGW)** | The AWS-side attachment point for an encrypted VPN or Direct Connect | Only allows traffic from an **approved network**. VPC = boundary, VPN = tunnel, **VGW = the door** | 4 |
| **AWS Transit Gateway** | Central hub connecting many VPCs and on-premises networks | Replaces a mesh of point-to-point links. Inter-Region peering over the AWS backbone | 4 |
| **AWS Client VPN** | Connects **individual remote workers** to AWS/on-premises | Fully managed, elastic, OpenVPN-based. Signal: *"remote workforce", "scale user access"* | 4 |
| **AWS Site-to-Site VPN** | Encrypted tunnel between a **whole site** (data center, branch) and your VPC | Over the public internet, up today, cheap. Needs a **customer gateway** + **VGW or Transit Gateway** | 4 |
| **AWS PrivateLink** | Privately connect your VPC to services/other VPCs **as if they were local** | **No IGW, NAT, public IP, Direct Connect or VPN needed.** Signal: *"must not traverse the public internet"* | 4 |
| **AWS Direct Connect** | **Dedicated private physical circuit** from your network to AWS | Consistent low latency, high bandwidth, lower transfer cost. **Weeks to install. NOT encrypted by default.** Use **two, at two DX locations** for HA | 4 |
| **Amazon Route 53** | DNS — translates domain names to IP addresses; also a domain registrar | Global, auto-scaling. Routes to AWS **and** non-AWS infrastructure. *Port 53 → the name* | 4 |
| **Amazon CloudFront** | CDN — **caches** content at edge locations near users | Faster loads, lower origin load, lower cost. Origin = S3, EC2, ELB, or external | 4 |
| **AWS Global Accelerator** | Routes traffic over the **AWS private backbone** with fast failover | **Optimizes the path, doesn't cache.** For non-HTTP / dynamic traffic: gaming, VoIP, IoT. Two **static anycast IPs** | 4 |
| **Security group** | Virtual firewall at the **instance** level | **Stateful** (return traffic auto-allowed), **allow rules only** — cannot deny. Default: deny all in, allow all out | 4 |
| **Network ACL** | Virtual firewall at the **subnet** level | **Stateless** (must allow return traffic explicitly, incl. ephemeral ports 1024–65535), **allow *and* deny**, evaluated in **numbered order** | 4 |

### 1.4 Storage

| Service | What it does | Key facts / when to use | M |
|---|---|---|---|
| **EC2 instance store** | Temporary block storage **physically attached to the host** | **Survives reboot; lost on stop/terminate.** Fastest option. Buffers, caches, scratch data only | 5 |
| **Amazon EBS** | Persistent block volumes for EC2 — like an external hard drive | **One AZ, one instance** at a time. Types: **gp3/gp2** (general SSD), **io2/io1** (provisioned IOPS), **st1** (throughput HDD), **sc1** (cold HDD) | 5 |
| **EBS snapshots** | Point-in-time, **incremental** backups of a volume | Stored **in S3 across multiple AZs**. Each restores a **full** volume; deleting one removes only its unique blocks. The way to move a volume to another AZ/Region | 5 |
| **Amazon Data Lifecycle Manager** | Automates snapshot creation, retention, and deletion | Schedule off-peak, auto-delete old ones. Also tags, archiving, fast snapshot restore, cross-Region copy, cross-account share | 5 |
| **Amazon S3** | Object storage — objects in buckets, accessed over HTTP | **11 nines durability**, 99.99% availability. **Flat namespace** (no real folders). Bucket names **globally unique**; buckets are **Regional**. **Private by default** | 5 |
| **S3 Lifecycle** | Rules that move objects between classes and delete them | **Transition** actions + **expiration** actions. Write once, applies forever | 5 |
| **Amazon EFS** | Elastic **NFS** file system, shared by many instances at once | **Multi-AZ, regional**, grows/shrinks automatically, pay for what's used. Classes: Standard, Standard-IA, One Zone, One Zone-IA, Archive | 5 |
| **Amazon FSx** | Managed **third-party** file systems | **Windows File Server** (SMB/AD) · **Lustre** (HPC/ML) · **NetApp ONTAP** · **OpenZFS**. Use when the app needs that exact protocol | 5 |
| **AWS Storage Gateway** | Makes cloud storage look like local storage to on-premises systems | **S3 File Gateway** (NFS/SMB → S3) · **Volume Gateway** (iSCSI; cached = data in cloud, stored = data local + EBS snapshot backups) · **Tape Gateway** (virtual tape library) | 5 |
| **AWS Elastic Disaster Recovery** | Continuously replicates physical/virtual/cloud servers into AWS | No idle secondary data center; **non-disruptive DR testing**; fast failover | 5 |
| **AWS Backup** | One dashboard and policy set for backups across services and accounts | Covers EBS, EFS, RDS, DynamoDB, FSx, S3 and on-prem via Storage Gateway. **Cross-Region**, audit logs, auto-protects new resources | 6 |

| **Amazon DocumentDB** | Managed **MongoDB-compatible** document database | JSON documents, dynamic schemas, **64 TB**, **15** replicas. Signal: the word *MongoDB* | 6 |
| **Amazon Neptune** | Purpose-built **graph** database | Property graph + RDF. **Billions of relationships in milliseconds**, 64 TB. Social networks, **fraud detection**, recommendations | 6 |

## 2. Topic tables

### 2.1 Scope — global vs. Region vs. AZ

| Scope | Services / resources |
|---|---|
| **Global** | IAM · Route 53 · CloudFront · WAF · Shield · Organizations · Billing · S3 **bucket names** |
| **Regional** | S3 buckets · DynamoDB · Lambda · RDS/Aurora · VPC · SQS/SNS · ECS · **EBS snapshots** · **AMIs** |
| **Availability Zone** | EC2 instances · **EBS volumes** · subnets · RDS instances |

**Consequences:** an EBS volume attaches only within its AZ · AMIs and snapshots must be
**copied** between Regions · a VPC spans AZs but a subnet doesn't · nothing leaves a Region
unless you move it.

### 2.2 The three storage types

| | **Block** | **Object** | **File** |
|---|---|---|---|
| Data is | Raw blocks on a volume | Whole objects, flat namespace | Files in a folder tree |
| Change 1 byte | Rewrite that **block** | Rewrite the **whole object** | Rewrite part of the file |
| Attached to | **One** instance | Nothing — HTTP API | **Many** instances |
| Services | instance store, **EBS** | **S3** | **EFS, FSx** |

**The test:** how many machines need it at once? **One → block. Many → file. Over the web → object.**

### 2.3 S3 storage classes

| Class | AZs | Retrieval | Use for |
|---|---|---|---|
| **S3 Standard** | ≥3 | ms | Default; frequently accessed |
| **Intelligent-Tiering** | ≥3 | ms | **Unknown or changing** access patterns — AWS moves it for you |
| **Standard-IA** | ≥3 | ms | Infrequent but needs fast access; retrieval fee |
| **One Zone-IA** | **1** | ms | Infrequent **recreatable** data / secondary backups |
| **Express One Zone** | **1** | **single-digit ms** | Most frequently accessed, latency-critical |
| **Glacier Instant Retrieval** | ≥3 | **ms** | Archive needing instant access; ~68% cheaper than Standard-IA |
| **Glacier Flexible Retrieval** | ≥3 | **1–5 min** / 5–12 h | Accessed 1–2×/year; backup, DR |
| **Glacier Deep Archive** | ≥3 | **12 h** | **Cheapest**; 7–10+ year regulatory retention |
| **S3 on Outposts** | on-prem | local | Local data residency |

**The three questions:** how often read · how fast must it come back · can you lose one AZ.

### 2.4 EC2 instance families

| Family | Optimized for | Typical workloads |
|---|---|---|
| **General purpose** (M, T) | Balanced | Web servers, dev/test, *"requirements uncertain"* |
| **Compute optimized** (C, Hpc) | High CPU | Batch, gaming servers, HPC, scientific modeling |
| **Memory optimized** (R, X, U, Z) | Large RAM | In-memory caches, big databases, real-time analytics |
| **Accelerated computing** (P, G, Inf, Trn, F, VT) | GPU/FPGA/ASIC | ML training and inference, graphics, video transcoding |
| **Storage optimized** (I, Im, Is, D) | Local disk IOPS | Data warehouses, NoSQL, heavy local I/O |

Name format: `m7gd.xlarge` = **m** general purpose · **7** gen · **g** Graviton · **d** local
NVMe · size. Suffixes: `a` AMD · `i` Intel · `g` Graviton · `n` network optimized · `z` high
frequency.

### 2.6 Pricing fundamentals

**Three concepts:** pay as you go · save when you commit · pay less by using more (tiered).
**Three cost drivers:** **compute** (per time) · **storage** (provisioned/used) ·
**outbound data transfer** (**inbound and same-Region are free**).
**S3's six cost components:** storage · requests & retrieval · transfer · data management &
analytics · replication · Object Lambda.

**Cost optimization order:** delete unused → right-size → turn off → tier storage →
**then** commit (Savings Plans/RI) → Spot for the interruptible.
*Committing before right-sizing locks in the waste for 1–3 years.*

### 2.8 Shared Responsibility Model

**AWS secures *of* the cloud · you secure *in* the cloud.** The line moves by service:

| Service | AWS handles | You handle |
|---|---|---|
| **EC2** | Hardware, hypervisor | **Guest OS, patching, firewall rules, app, data** |
| **RDS** | Hardware, OS, **DB engine patching** | DB users, network placement, data |
| **S3** | The entire storage service | **Bucket policies, access settings, encryption, data** |
| **Lambda** | Everything up to the runtime | **Your code, its IAM role, data** |

**Always yours, at every level: your data and who can reach it.**

## 6. Top traps

1. **IAM defaults to deny**; an **explicit deny always wins**.
2. **A security group cannot block an IP** — allow rules only. Use a **NACL**.
3. **NACLs are stateless** — allow return traffic explicitly (ephemeral ports).
4. **An SCP never grants** — it caps, and **binds account admins too**.
5. **Assuming a role replaces your permissions**; it doesn't add to them.
6. **Never put an access key on EC2** — attach a **role**.
7. **Instance store survives reboot, dies on stop/terminate.**
8. **EBS is locked to one AZ and one instance.** Cross-AZ ⇒ snapshot.
9. **Snapshots are incremental** but each restores a **full** volume.
10. **S3 has no folders** — flat namespace.
11. **Durability (11 nines) ≠ availability (99.99%).**
12. **Glacier Instant Retrieval is milliseconds** — not all Glacier is slow.
13. **Multi-AZ standby isn't readable**; read replicas don't auto-fail over.
14. **A cache is a copy**, never the source of truth.
15. **CloudWatch = performance · CloudTrail = who did what · Config = configuration.**
16. **CloudTrail free history is 90 days** — longer needs a trail to S3.
17. **Detective investigates; GuardDuty detects; Inspector scans for vulnerabilities.**
18. **Direct Connect is private but not encrypted.**
19. **One Direct Connect link is a single point of failure.**
20. **CloudFront caches; Global Accelerator routes.**
21. **Fargate replaces EC2 underneath ECS/EKS**, not ECS/EKS.
22. **Lambda's 15-minute cap** rules out long jobs → Batch/ECS/EC2.
23. **Inbound data transfer is free; outbound is charged.**
24. **Six Well-Architected pillars**, not five.
25. **Commit to Savings Plans last**, after cleanup and right-sizing.
26. **AMIs and snapshots are Region-scoped** — copy them to move Regions.
27. **RDS supports six engines — MongoDB is not one** (that's DocumentDB).
28. **Business Support is the first production tier**; only **Enterprise** gets a
    **designated** TAM.
29. **Retain and Retire are migration strategies** — decisions not to move.
30. **The Well-Architected Tool and Migration Hub are free**; you pay only for resources.
